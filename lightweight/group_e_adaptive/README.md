# E 组动态蒸馏实验

在包含原 E 组的 CIGPose-FYP 仓库根目录解压本包。ZIP 新增
`lightweight/group_e_adaptive/`。用此前已能运行 E 组的单 GPU Linux/WSL 环境、
官方教师权重、固定 30% 数据及完整 val2017，启动一次独立训练。

## 启动和恢复

```bash
python -u lightweight/group_e_adaptive/train.py \
  --teacher /path/to/cigpose-m_coco_256x192.pth \
  --temperature 0.1 \
  --work-dir work_dirs/group_e_adaptive_t01
```

中断后，等原进程退出，将同一条命令加上 `--resume`。保留同一输出目录、
温度、代码和数据。每 10 轮保存常规 checkpoint，`last_checkpoint` 指向最近一份。
从已保存的轮次继续，未保存的轮次会重跑。新实验从原 E 组初始化流程开始，
续训使用本实验生成的 checkpoint。保留输出目录内的 `run_manifest.json`
和 `diagnostic_batches.pth`，后者包含实际增强后的五个诊断 batch。
原训练加载器的数据增强随机序列在重启后可能变化。诊断批次会逐字节复用。

若比较温度 0.2，使用 `--temperature 0.2` 和另一输出目录，从头跑完整对照。
两组使用同一套动态目标、门控和退火规则。两组独立建立固定诊断缓存时，
在相同数据、种子和软件环境下会采用相同采样和增强设置。

## 计算和日志

- 门控使用原始 COCO 可见性 v=1，并按训练时的水平翻转重排关节。对经过裁剪、
  仿射和编码后仍有效的遮挡点，在增强输入图的像素坐标上比较师生的二维欧氏误差。
  只有教师误差严格更小才放行。可见点沿用原有规则。SimCC KL 的分母仍为门控前
  的有效点总数。
- 每轮开始前，在缓存的五批上独立求 GT、CF、加权 SimCC 和加权 Pre-CIM 的梯度。
  每批统一用 loss scale 1024，溢出时降低同一批的共同 scale。还原梯度后以 FP64
  累计向量内积。日志中的求和校验比较基础权重下的分项梯度之和与直接求总损失的梯度。
  调权前后四项范数、投影和余弦从同批内积计算。全模型及骨干、CIM、GNN
  和其他层分别记录，分模块投影的分母是该模块总梯度的平方范数。
- 前 80 轮以全模型两项蒸馏的平均合计投影贡献为控制量。40%–50% 内沿用系数，
  超出时在基础系数的共同倍率 0.01–100 内搜索，优先靠近 45%。没有达标候选
  或诊断无效时沿用上一轮倍率并明记原因。第 81 轮使用第 80 轮系数的 95%，
  之后线性下降，第 100 轮为 0。退火阶段继续记录诊断数据，供后续分析。
- 诊断不做优化器更新，逐批恢复学生缓冲区，结束后恢复模式及随机状态。
  调权针对诊断批次每轮开始时的平均值。实际训练批次的贡献会波动。

| 文件 | 内容 |
|---|---|
| `run_manifest.json` | 代码提交和文件哈希、数据文件及版本、训练环境、师生初始化、超参数、诊断增强配置、样本 ID 和批次划分 |
| `gradient_epochs/epoch_XXX.json` | 调整前后系数和投影贡献、是否达标、倍率搜索记录、退火状态，以及五批的各模块梯度范数、投影、余弦、loss scale 和求和误差 |
| `loss_history.csv` | 每轮训练与验证损失、各 KD 的原始和加权损失、门控统计、分组学习率、耗时和 AMP 跳步数 |
| `ap_history.json` | 每 10 轮的 AP、AP50、AP75，以及可见和遮挡关节的原图像素误差、归一化误差和数量 |
| `summary.json` | 最终结果与最佳 AP 轮次 |
| `epoch_*.pth` | 原训练 checkpoint 状态和动态系数、共同倍率、退火起点、已有损失与 AP 记录 |

日志中的投影贡献和门控放行率用小数表示，如 0.45 表示 45%。
门控误差的单位是增强输入图像素，验证误差的单位是原图像素。
